# WaysGram

WaysGram — Android-клиент на основе исходного Android-кода Telegram. Продукт и пользовательский интерфейс называются WaysGram; серверная часть работает через единый WaysGram AuthBot.

## Сборка APK

Проект использует GitHub Actions: `.github/workflows/android.yml`.

1. Открой вкладку Actions.
2. Выбери **WaysGram Android APK**.
3. Нажми **Run workflow**.
4. После успешного завершения скачай артефакт **WaysGram-APK**.

Workflow собирает исходник из девяти архивных частей, восстанавливает исходное дерево Android и подключает WaysGram REST к существующим экранам. В APK отображаемое имя приложения — WaysGram во всех десяти локалях.

Для подключения к развёрнутому AuthBot добавь в настройках GitHub-репозитория секрет **`WAYSGRAM_API_BASE_URL`** со значением HTTPS-адреса сервера без конечного пути API. Workflow передаёт его Gradle как manifest placeholder. Секрет не записывается в исходники. Без него APK может собраться, но вход WaysGram будет закрыт с сообщением о ненастроенном API. Резервного перехода на Telegram MTProto для входа нет.

## Оригинальный интерфейс и native integration

**Интерфейс не перерисовывается и не заменяется.** WaysGram использует штатные экраны, компоненты, навигацию, диалоги, вкладки, оформление, цвета, иконки и ресурсы из предоставленного исходного Android-архива Telegram. Отдельных Portal/Home-экранов, самодельного главного меню или новых визуальных оболочек нет. Launcher name изменён на WaysGram; оригинальная иконка и визуальные ресурсы сохранены.

- `apply_native_ui_v11.py` сохраняет переход IntroActivity → оригинальный LoginActivity, удаляет только прежний самодельный WaysGram Portal CTA и отладочный переключатель `Test Backend`; все `values*/strings.xml` получают единое имя приложения WaysGram.
- `configure_api_client.py` устанавливает REST-клиент, читает HTTPS endpoint из build-time manifest metadata и добавляет `WaysGramApiConfig`.
- `configure_api_runtime.py` инициализирует единый экземпляр `WaysGramApiClient` в `ApplicationLoader`.
- Сетевые классы и их внутренний Java namespace находятся в `app.waysgram.network`; старый пакет больше не используется для WaysGram-кода.
- `configure_native_messenger.py` подключает WaysGram REST к штатным `LoginActivity.PhoneView` / SMS code view, `MessagesController` и `SendMessagesHelper`.
- `WaysGramDataMapper.java` переводит серверные профили, диалоги и текстовые сообщения в native-модели для отображения существующими `DialogsActivity` и `ChatActivity`.
- `verify_original_ui.py` на каждой полной сборке сравнивает исходники всех экранов `org/telegram/ui` (кроме LoginActivity, куда добавлены только обработчики WaysGram-входа) с оригинальным архивом; также побайтово проверяет остальные UI Java-классы и Android UI-ресурсы. Все ресурсы, кроме локализованных `strings.xml`, должны оставаться идентичными оригиналу.

Патчи идемпотентны. Отдельный workflow **WaysGram Android Patch Tests** проверяет их повторное применение и проверку сохранения оригинального интерфейса на Python 3.11 и 3.12 без полной Android/NDK-сборки. Изменения в `waysgram/**` также запускают полную APK-сборку.

## Backend и текущий статус интеграции

Единый серверный репозиторий: [WaysGram-AuthBot](https://github.com/WeteroScript/WaysGram-AuthBot).

В AuthBot реализованы API авторизации через виртуальный номер и код из Telegram-бота, пользовательские сессии, профили, текстовые личные сообщения, текстовые каналы, внутренние Stars/Gram балансы и коллекционные подарки. Админ-панель находится только внутри Telegram-бота.

**В Android уже подключён ограниченный native REST bridge:**
- экран ввода виртуального номера отправляет запрос кода в AuthBot;
- штатный экран ввода SMS-кода проверяет WaysGram OTP и получает API-сессию;
- список диалогов загружается через `GET /api/conversations`;
- история личного текстового диалога загружается через `GET /api/messages` с курсорами;
- отправка обычного текстового личного сообщения идёт через `POST /api/messages`;
- при отсутствии `WAYSGRAM_API_BASE_URL` вход закрывается с сообщением о конфигурации, а не переключается на Telegram MTProto;
- список диалогов, история и отправка текста остаются на WaysGram-пути даже после истечения/удаления API-сессии; скрытого возврата этих операций к MTProto нет.

**Ограничения текущего bridge:**
- только текстовые личные диалоги; вложения, фото, видео, документы, ответы, реакции и форматирование ещё не подключены;
- групповые чаты, супергруппы и каналы пока не подключены к native UI;
- фоновая синхронизация, push-уведомления, звонки и медиа-транспорт ещё используют отсутствующие или прежние интеграции;
- настройки профиля, каталог и инвентарь подарков, кошелёк и управление каналами пока доступны в API, но ещё не все выведены в штатные Android-экраны;
- на устройстве и в процессе приложения используется локальная native Telegram-модель пользователя для отображения интерфейса; полноценная замена всех MTProto-зависимостей ещё не завершена. Другие не перенесённые подсистемы всё ещё требуют отдельной миграции.

Поэтому текущая стадия — частичная миграция авторизации и текстовых личных сообщений, а не полностью независимый от MTProto мессенджер.

## Исходники

В репозитории хранятся части исходного Android-архива и repeatable patch scripts в `waysgram/`. Полная Android-сборка выполняется GitHub Actions с восстановлением исходников и сборкой native-библиотек.

Технический Android `applicationId` пока остаётся `app.nexusgram`, поскольку текущий Firebase-конфиг привязан именно к нему. Это системный идентификатор приложения, а не отображаемое название; его смена требует нового Firebase Android app и соответствующего `google-services.json`.

Перед распространением APK необходимо проверить лицензии исходного проекта и используемых компонентов.
